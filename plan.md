

## Live Ayra bot status and server-count integration
- The public bot repository `cf7yce/Ayra` uses Node.js ES modules and discord.js 14.27; Railway starts it with `pnpm start`. It already has the authoritative `client.guilds.cache.size` count in its Discord stats command, but no HTTP server or HTTP-framework dependency. The supplied Railway host returned HTTP 502 (`Application failed to respond`) on its root and common test paths because no web listener is present.
- Add a small built-in `node:http` server to the bot process, binding `0.0.0.0` on Railway's `PORT`. Serve a health check and a read-only `GET /api/stats` response with only current Discord client state and the actual guild/server count. Report online only when discord.js says the client is ready; return a null count before readiness. Do not expose member counts, IDs, bot tokens, database contents or diagnostics; add no dependency.
- In Ayraweb, add a same-origin server route `/api/bot-stats` with a short timeout, `no-store` behavior, strict validation and an unavailable fallback. Add a lightweight homepage widget that polls periodically, displays the actual online state and server count, and never fabricates numbers or displays member counts.
- Publishing constraint: the current GitHub CLI identity has `READ` permission on `cf7yce/Ayra`; do not push there until the owner account is authorized or write access is granted. Ayraweb's separate repository scope remains unchanged.
